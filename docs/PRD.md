## 1. 背景与问题

普通投资者（散户）在做美股决策时面临三个痛点：

1. **信息过载**：每天海量新闻、财报、社交媒体讨论，无法快速判断哪些与自己持仓相关、是利好还是利空。
2. **缺乏工具门槛高**：专业量化平台（如 backtrader、QuantConnect）要求会写代码、懂统计，散户用不起来。
3. **决策情绪化**：缺乏系统化的信号和回测验证，容易追涨杀跌。

**机会**：LLM + 新闻情绪分析的成熟，使得"把专业量化能力包装成普通人能用的产品"成为可能——用户不写代码，也能获得基于新闻情绪 + 技术指标的、**可解释**的信号和回测结果。这正是 Pulse 的立足点：让用户**感知市场脉搏，过滤噪音**。

## 2. 产品目标与定位

**一句话定位**：Pulse 让不懂代码的普通投资者，也能用"新闻情绪 + 量化信号"系统化地辅助美股决策。

**核心价值主张**：
- 把分散的新闻/情绪/行情**聚合成一眼能看懂的信号**（"市场脉搏"）。
- 提供**可解释**的理由（"为什么给出这个信号"），而非黑箱。
- 内置**回测**，让用户在投入真金白银前先看历史表现。
- 强调**辅助决策**，不替用户下单（合规与信任的底线，见第 9 节）。

**Pulse 不是什么**（避免错位）：
- ❌ 不是自动交易机器人（MVP 不接实盘下单）。
- ❌ 不是投资顾问 / 不提供投资建议（合规要求）。
- ❌ 不是面向专业量化的编程平台。

## 3. 目标用户

| 画像 | 描述 | 核心诉求 |
|------|------|---------|
| **小白投资者** | 有美股账户（如 Robinhood/富途），靠新闻和朋友推荐做决策 | 看懂"现在该关注什么"，避免踩雷 |
| **进阶散户** | 会看 K 线和基本面，想要系统化信号验证自己的判断 | 信号 + 回测，验证 idea |
| **学习者** | 想入门量化但被代码门槛劝退 | 低门槛体验量化思路 |

**非目标用户**：专业机构、需要超低延迟/高频的用户、需要自定义复杂策略代码的量化工程师。

## 4. 范围与 MVP

### 4.1 MVP（第一版必须有）
- 自选股 watchlist 管理
- 每只股票的**每日新闻情绪聚合 + 情绪评分**（可解释：列出关键新闻）
- **量化信号卡片**：综合情绪 + 基础技术指标（如均线、RSI），给出"关注/中性/谨慎"的可解释提示
- 简易**回测**：在预设的几个内置策略上，展示历史收益/最大回撤/胜率曲线
- 风险提示与免责声明（贯穿全程）

### 4.2 后续迭代（明确排除在 MVP 外）
- 策略自定义（拖拽式 no-code 策略构建器）
- 组合层面的分析与再平衡建议
- 实盘交易接口（需券商对接 + 更强合规）
- 移动端 App
- 社区/策略分享

## 5. 功能需求

### F1. 自选股管理
- 添加/删除/分组自选股；支持搜索美股 ticker。
- 展示每只股票的实时/延迟价格、当日涨跌、情绪分概览。

### F2. 新闻情绪聚合（核心）
- 自动拉取每只自选股的相关新闻（带**精确发布时间戳**）。
- 用情绪模型（FinBERT / LLM）为每条新闻打分，聚合成股票级**日度情绪分**（如 -1 ~ +1），即该股的"脉搏"。
- **可解释**：点击情绪分可展开当日驱动该分数的关键新闻标题、来源、链接、单条情绪。
- 处理"无新闻"情况：标记为中性，不误导。

### F3. 量化信号卡片（核心）
- 综合「情绪分 + 技术指标（均线、RSI、动量）」输出一个**分级信号**（如：积极关注 / 中性 / 需谨慎）。
- 每个信号附**理由说明**（哪些因子在起作用），强调"仅供参考"。
- 明确展示信号的**历史命中率**（来自回测），避免给用户"一定准"的错觉。

### F4. 回测（核心）
- 提供 3~5 个内置策略（如"情绪反转""情绪 + 动量"）。
- 用户选股票 + 时间段 + 策略，一键回测。
- 输出：累计收益曲线 vs 基准（如 SPY）、年化收益、最大回撤、Sharpe、胜率、交易次数。
- **必须扣除手续费和滑点**，并默认开启，避免理想化结果。
- 显著标注**前视偏差风险**（见第 10 节技术风险）。

### F5. 提醒与推送（MVP 可选/简版）
- 当某只自选股情绪分或信号发生显著变化时，通知用户（"脉搏异动提醒"）。

### F6. 合规与教育模块
- 全程免责声明；首次使用强制阅读"这不是投资建议"。
- 内置简短的概念解释（什么是情绪分、什么是回测、为什么历史不代表未来）。

## 6. 用户流程（MVP 主流程）

```
注册/登录
  → 添加自选股（watchlist）
    → 查看股票详情页：价格 + 情绪分（脉搏） + 信号卡片（含理由）
      → 展开查看驱动新闻（可解释）
      → 点击"回测这个信号" → 选时间段/策略 → 看历史表现
        → 设置脉搏异动提醒（可选）
```

## 7. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 详情页加载 < 2s；回测结果 < 10s 返回 |
| 数据新鲜度 | 新闻情绪每日至少更新 1 次（盘前），价格可用延迟数据（标注延迟） |
| 可用性 | 面向小白，零代码、零术语门槛，关键术语都有 tooltip 解释 |
| 可解释性 | 任何信号/分数都能下钻到原始依据 |
| 安全 | 用户数据加密；API key 服务端保管，不下发客户端 |
| 成本 | 数据源按额度计费，需做缓存与限流控制单用户成本 |

## 8. 数据来源

| 类型 | 候选数据源 | 说明 |
|------|-----------|------|
| 行情（价格/成交量） | Alpaca / Polygon / yfinance（研究期） | 需复权价；用 `pandas-market-calendars` 处理交易日 |
| 新闻 + 情绪 | Alpha Vantage（News&Sentiment）/ Finnhub / EODHD | 必须带精确发布时间戳，便于 point-in-time |
| 情绪模型 | FinBERT（ProsusAI/finbert）或 LLM | 情绪分单独存储、可重算 |
| 基本面（后续） | FMP / SEC EDGAR | 估值/财报因子 |

> 数据层设计原则：**原始数据落地（带时间戳）与使用分离**，新闻 schema 至少含 `symbol, published_at(UTC), source, headline, body, url, sentiment_score`，情绪分单列、可重算。

## 9. 合规与风险声明（务必重视）

面向普通用户的金融工具，合规是**生死线**，不是事后补充：

1. **明确定性为"信息工具"而非"投资顾问"**：不提供个性化投资建议，不承诺收益。避免触发投顾牌照（如美国 SEC/FINRA 的 RIA 监管）。
2. **全程免责声明**：所有信号、回测、情绪分旁均需注明"仅供参考，不构成投资建议，投资有风险"。
3. **不替用户决策/下单**（MVP 阶段）：降低法律责任与信任风险。
4. **历史不代表未来**：回测页面强制展示该提示。
5. **数据合规**：遵守各数据源的商用授权条款（如 yfinance 不可商用，仅限研究）。
6. **隐私**：用户持仓/自选属敏感数据，需合规存储与隐私政策。

> 建议在产品立项阶段就咨询法务，明确目标市场（美国）的具体监管边界。

## 10. 技术风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **前视偏差（look-ahead bias）** | LLM 可能"记得"历史新闻后续走势，回测虚高，实盘失效 | 回测只用模型训练截止后的新闻做样本外验证；信号严格用 point-in-time 数据；可做新闻匿名化 |
| 过拟合 | 内置策略在历史上好看、未来失效 | 样本外测试；展示真实扣费后表现；不过度宣传 |
| 数据质量 | 缺失/错误价格、重复新闻 | 入库前数据校验断言；去重；缺口检测 |
| 数据成本失控 | 用户增长导致 API 费用激增 | 服务端缓存、按股票池共享、限流 |
| 用户误解信号为"稳赚" | 信任崩塌 + 合规风险 | 强可解释 + 命中率展示 + 免责声明 |

## 11. 成功指标（North Star & 辅助指标）

- **North Star**：每周活跃使用信号/回测功能的用户数（WAU on core features）。
- 辅助：自选股平均数量、回测使用率、新闻下钻点击率、7日/30日留存、单用户数据成本。

## 12. 路线图（建议）

| 阶段 | 内容 | 目标 |
|------|------|------|
| **P0 数据层** | 行情 + 新闻（带时间戳）落地、情绪打分管道、point-in-time 查询 | 打好地基（当前优先） |
| **P1 MVP** | 自选股 + 情绪聚合 + 信号卡片 + 简易回测 + 合规模块 | 可用闭环，小范围内测 |
| **P2 增强** | 提醒推送、更多内置策略、可解释优化 | 提升留存 |
| **P3 扩展** | no-code 策略构建器、组合分析、移动端 | 拉开差异化 |
| **P4（谨慎）** | 实盘交易对接 | 需更强合规与风控 |

## 13. 开放问题（待决策）

1. 商业模式：免费 + 订阅？按数据额度？这影响数据源选型和成本结构。
2. 价格数据用实时（贵、需授权）还是延迟（免费、需标注）？
3. 情绪模型用本地 FinBERT（可控、便宜）还是 LLM API（更强、更贵、有前视偏差风险）？
4. 目标地区是否仅限美国用户？涉及不同合规要求。
5. MVP 是否需要登录/账户体系，还是先做无账户的体验版？
